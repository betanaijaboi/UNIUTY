Test Plan

Comprehensive test strategy for the UNIUTY Portal covering all test types, environments, test cases, UAT procedure, and release sign-off requirements.

1. Objectives

  • Verify that all features meet their acceptance criteria as documented in acceptance-criteria.html
  • Ensure the system is secure against common web vulnerabilities (OWASP Top 10)
  • Validate that the system performs under the expected load of 15,000 concurrent users
  • Confirm that biometric integrations function correctly with real hardware
  • Ensure NDPR compliance controls are in place and auditable
  • Obtain sign-off from representative stakeholders in all four user roles before go-live

3. Test Types

3.1 Unit Tests

Tool: Jest | Coverage Target: ≥ 80% per module | Runner: GitHub Actions on every PR

  • Grade Calculation: gradeCalc(ca, exam) → { total, grade } — all boundary conditions (0, 30, 70, 100, fractions)
  • CGPA Calculation: calcCGPA(results[]) — weighted average over multiple semesters
  • Password Validation: validatePassword() — rejects weak; accepts strong; checks HIBP list
  • Role Detection: hasPermission(role, action) — all 4 roles × all 20 permissions
  • JWT Utilities: signToken(), verifyToken(), isTokenDenylisted() — expiry, tamper, blacklist
  • Matric Number Generator: generateMatric(year, dept, seq) → correct format
  • Fee Balance Calculator: calcBalance(total_amount, payments[]) → correct balance
  • Attendance Percentage: calcAttendancePct(sessions_held, sessions_attended) → correct percentage

3.2 Integration Tests

Tool: Jest + Supertest | Scope: API endpoint contracts with real DB (test schema)

  • Login flow: POST /auth/login → JWT returned; POST /auth/refresh → new token; POST /auth/logout → token denied
  • Result submission with biometric: POST /results (with valid bio_token) → batch created; POST /results (without bio_token) → 401
  • Fee payment webhook flow: POST /payments → checkout_url returned; simulate Remita webhook → fee balance updated; GET /fees/:id → balance = 0
  • Biometric enrollment → verify → delete cycle
  • User creation and role change with audit log verification
  • Account lockout after 5 failed logins

3.3 End-to-End (E2E) Tests

Tool: Playwright | Environments: Staging (pre-production data) | Runs: Nightly + before every release

  • Student Journey: Login → view results → download transcript (no balance) → pay fees → transcript unlocked
  • Lecturer Journey: Login → navigate to course → enter scores → save draft → submit with biometric → receive admin feedback → correct and resubmit
  • Admin Journey: Login → create user → assign to department → approve result batch → publish → verify student notification received
  • VC Journey: Login → view executive dashboard → drill into department → view audit log → approve role promotion
  • Password Recovery: Visit forgot-password → enter email → receive OTP → reset password → login with new password

User Acceptance Testing will be conducted in Week 17–18 in a controlled staging environment with real user data (anonymised). Three sign-off groups are required:

6.2 UAT Sign-off Checklist

  • All critical user journeys completed without system error by each group
  • No P1 or P2 defects outstanding at time of sign-off
  • Each group lead signs the UAT Acceptance Form
  • Feedback collected and triaged — cosmetic issues documented as P4 (post-launch backlog)

8. Release Sign-off Criteria

Production release is approved only when ALL of the following are satisfied:

Go / No-Go Decision Gate: This checklist must be reviewed by the Project Manager, ICT Director, QA Lead, and VC Representative in a Release Readiness meeting before deployment is authorised.
  • All P1 and P2 defects are resolved and re-tested as PASS
  • All test types have been executed: Unit, Integration, E2E, Performance, Security
  • Performance test passes: P95 load time < 2s at 15,000 concurrent users
  • Security pen test completed; all Critical and High findings remediated
  • UAT sign-off forms received from all four stakeholder groups
  • Data migration completed and verified: record count, sample spot checks
  • Biometric enrollment ≥ 90% of active users (minimum pre-launch)
  • Backup and recovery test passed: data restored from backup within RTO
  • Monitoring dashboards live and alerting tested (UptimeRobot, Sentry, New Relic)
  • NDPR DPIA reviewed and signed by DPO
  • Rollback procedure documented and rehearsed
  • Staff training completed for all Admin and Lecturer users
