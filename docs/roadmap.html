Project Roadmap & Milestones

A four-phase delivery plan taking UNIUTY Portal from initial MVP through full-scale multi-campus expansion, with milestones, team composition, and a risk register.

Delivery Model: Agile sprints (2-week cadence). Start Date: Week 1 = 7 July 2026. Full Go-Live Target: Week 22 = 20 November 2026.

1. Overview

PhaseDurationThemeKey Deliverable
Phase 1Weeks 1–8MVPCore auth, role portals, result posting, simulated biometrics
Phase 2Weeks 9–16BetaReal biometric hardware, fee payment, attendance, audit logs
Phase 3Weeks 17–22LaunchUAT, security audit, performance hardening, go-live
Phase 4Months 6–12ScaleMulti-campus, mobile app, advanced analytics, AI fraud detection

2. Phase Details

01 Phase 1 — MVP (Weeks 1–8) In Progress

Sprint 1–2: Foundation & Infrastructure (Weeks 1–4)

  • Set up monorepo, GitHub Actions CI/CD pipeline, Docker dev environment
  • Design and migrate PostgreSQL schema (all 14 tables)
  • Implement JWT authentication, bcrypt password hashing, RBAC middleware
  • Build Admin user management CRUD: create, read, update, suspend, delete
  • Implement session management, token refresh, logout with Redis denylist

Sprint 3–4: Role Portals & Results (Weeks 5–8)

  • Build Student dashboard: results view, course list, basic profile management
  • Build Lecturer dashboard: assigned courses, result entry form, CSV upload
  • Build Admin dashboard: user list, result approval workflow, department management
  • Build VC dashboard: basic KPI summary, result overview
  • Implement simulated biometric (PIN fallback) for testing before hardware arrives
  • Result publication pipeline: submit → pending → approve → published
  • Email notification service integration (Nodemailer + SMTP)
M1.1 — Dev environment and CI/CD pipeline operational (End of Week 2)
M1.2 — All 4 role dashboards functional in dev environment (End of Week 6)
M1.3 — MVP demo to Steering Committee — result flow end-to-end (End of Week 8)
02 Phase 2 — Beta (Weeks 9–16) Planned

Sprint 5–6: Biometric Hardware Integration (Weeks 9–12)

  • Deploy BiometricAPI plugin interface with real hardware driver (Suprema BioStation)
  • Fingerprint, retina, facial scan, and NFC enrollment flows
  • Biometric verification at exam entry and attendance recording
  • Biometric log viewer for Admin and VC
  • AES-256 template encryption and secure vault schema
  • Liveness detection testing and quality threshold calibration

Sprint 7–8: Fees, Payments & Attendance (Weeks 13–16)

  • Remita and Flutterwave payment gateway integration
  • Fee invoice generation and payment webhook reconciliation
  • PDF receipt and payment history dashboard
  • NFC and facial attendance recording with real-time class counter
  • Attendance report generation (PDF export for Senate)
  • Full audit log implementation with HMAC integrity signatures
  • SMS notifications via Termii (payment receipts, attendance warnings)
M2.1 — Biometric hardware enrolled and verified for 50 test users (End of Week 12)
M2.2 — First live payment processed via Remita integration (End of Week 14)
M2.3 — Beta release to 200 pilot users (50 students, 20 staff) — End of Week 16
03 Phase 3 — Launch (Weeks 17–22) Planned

Sprint 9–10: UAT & Security Hardening (Weeks 17–20)

  • University Acceptance Testing with student reps, lecturer reps, admin reps, bursary
  • External penetration test (contracted to a certified NCC-licensed security firm)
  • OWASP Top 10 vulnerability remediation
  • Load testing: simulate 15,000 concurrent users (k6 test suite)
  • Performance tuning: slow query optimisation, Redis caching layer for hot paths
  • NDPR DPIA final review; DPO sign-off
  • Backup restoration drill: verify RPO ≤ 1h, RTO ≤ 4h

Sprint 11–12: Go-Live (Weeks 21–22)

  • Legacy data migration: 12,847 student records, 634 staff records from existing spreadsheets
  • Biometric mass enrollment campaign (ICT Centre — 3 weeks pre-launch)
  • Staff training workshops: Admins (2 days), Lecturers (1 day), Student orientation videos
  • Production deployment with blue-green strategy; canary release at 5% → 25% → 100%
  • Monitoring dashboards live: UptimeRobot, New Relic, Sentry
  • Hypercare support period: 2 weeks post-launch with 24/7 on-call rota
M3.1 — Security audit report completed; all critical findings resolved (End of Week 19)
M3.2 — UAT sign-off from all stakeholder groups (End of Week 20)
M3.3 — Production go-live for all 13,000+ users (End of Week 22 — 20 Nov 2026)
04 Phase 4 — Scale (Months 6–12) Future

Month 6–8: Multi-Campus Expansion

  • Tenant-aware data model activation (campus_id column on all entities)
  • Campus-level admin roles and isolation controls
  • Cross-campus reporting for VC and system superadmin
  • On-boarding of 2 satellite campuses with their own biometric hardware

Month 9–10: Native Mobile App (React Native)

  • iOS and Android apps wrapping portal APIs
  • Biometric login via device-native fingerprint (Face ID / Touch ID)
  • Push notifications for results, fees, and announcements
  • Offline mode for attendance viewing and results (read-only cache)

Month 11–12: Advanced Analytics & AI Fraud Detection

  • ML model trained on 2+ semesters of biometric and result data
  • Anomaly detection: flag unusual score patterns (e.g. entire class scoring 100% in CA)
  • Predictive analytics: at-risk student early warning system based on attendance + grades
  • VC analytics dashboard with trend charts, cohort analysis, and benchmarking
M4.1 — Second campus onboarded (Month 8)
M4.2 — Mobile apps published to App Store and Play Store (Month 10)
M4.3 — AI fraud detection system live with first semester of training data (Month 12)

5. Risk Register

IDRiskLikelihoodImpactOverallMitigation
R-01 Biometric hardware delivery delayed or incompatible with BiometricAPI Medium High High Simulated biometric mode in Phase 1; hardware vendor locked in by Week 4; 2 alternative vendor SDKs pre-evaluated
R-02 Remita payment gateway API changes or downtime during launch Medium Medium Medium Flutterwave implemented as hot standby; payment gateway abstraction layer enables < 1-hour switch
R-03 Legacy student data quality is poor — high error rate in migration CSV High Medium High Data audit begins Week 4; Registry dedicate 2 staff to clean source data; migration tool validates before importing
R-04 Low biometric enrollment adoption — students don't show up for enrollment sessions Medium High High Mandate biometric enrollment as requirement for exam clearance; multiple enrollment stations across campus; mobile enrollment unit
R-05 Poor internet connectivity in some campus buildings High Medium Medium Offline-capable attendance mode with sync on reconnection; ICT to audit and upgrade Wi-Fi coverage before launch
R-06 Staff resistance to biometric authentication Medium Low Low Staff consultation workshops in Phase 3; clear privacy policy communication; NDPR consent process transparent
R-07 Security breach during go-live period (targeted attack on new system) Low High Medium External pen test before launch; Cloudflare WAF active; Sentry + security alerts; incident response plan exercised
R-08 Key developer departure mid-project Low High Medium Full code documentation; Git history; pair programming for critical modules; onboarding docs up to date
R-09 Budget overrun due to hardware procurement or cloud costs Medium Medium Medium On-premise option (self-hosted VMs) as fallback for cloud cost; hardware budget locked in purchase order by Week 2
R-10 NDPR non-compliance identified in external audit Low High Medium DPIA completed in Phase 3; DPO reviews each phase; legal counsel review of data processing agreements
