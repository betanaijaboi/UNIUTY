Acceptance Criteria

Testable, unambiguous acceptance criteria for every major feature of the UNIUTY Portal, written in Gherkin (Given/When/Then) format for direct use in test case creation.

1. How to Read These Criteria

Format: Each criterion has a unique ID (e.g. AC-AUTH-01), a feature description, and one or more Gherkin scenarios. A feature is considered done when all its Gherkin scenarios pass in the staging environment AND are reviewed by the QA lead.
PrefixModule
AC-AUTHAuthentication & Session Management
AC-BIOBiometric System
AC-ADMINAdministrator Module
AC-LECLecturer Module
AC-STUStudent Module

2. Authentication

AC-AUTH-01
Successful Login with Valid Credentials
Given a user with portal_id "STU-2024-001" and a valid password exists in the system
When the user submits portal_id "STU-2024-001" and the correct password
Then the API returns HTTP 200
And the response contains a valid JWT access_token
And a uniuty_rt HttpOnly refresh token cookie is set
And the user's failed_attempts counter is reset to 0
AC-AUTH-02
Account Lockout After 5 Failed Attempts
Given a user has made 4 failed login attempts
When the user makes a 5th failed attempt
Then the account is locked (locked_until = NOW() + 30 minutes)
And the API returns HTTP 401 with error code ACCOUNT_LOCKED
And an unlock email is dispatched to the user's registered email within 60 seconds
And subsequent login attempts return HTTP 401 until the lockout expires
AC-AUTH-03
Password Reset via OTP
Given a user requests a password reset for their registered email
When a valid OTP and reset token are submitted with a new compliant password
Then the password is updated in the database
And all existing JWT sessions for the user are invalidated in Redis
And the user can log in with the new password
And the OTP is marked as used and cannot be reused
AC-AUTH-04
Expired OTP Rejection
Given a password reset OTP was generated 16 minutes ago
When the user submits this OTP
Then the API returns HTTP 401 with error OTP_EXPIRED
And the password is not changed
And the user is instructed to request a new OTP
AC-AUTH-05
JWT Refresh Token Flow
Given a user has an expired access token but a valid refresh token cookie
When the user calls POST /api/auth/refresh
Then a new access token is returned with HTTP 200
And the old access token is added to the Redis denylist
And the new token contains the same user_id and role claims
AC-AUTH-06
Role-Based Route Protection
Given a user is authenticated with role "student"
When the user calls GET /api/users (Admin/VC only endpoint)
Then the API returns HTTP 403 with error code FORBIDDEN
And no user data is returned in the response body

3. Biometric System

AC-BIO-01
Successful Biometric Enrollment
Given an admin is authenticated and the biometric terminal is online
When the admin enrolls 3 fingerprint samples for user "uuid-student-001" each with quality ≥ 70%
Then a combined template is created and stored encrypted in the biometric vault
And a record is written to biometric_log with method "fingerprint", purpose "enrollment", and result "SUCCESS"
And the student's biometric enrollment status shows Fingerprint: Enrolled
AC-BIO-02
Biometric Verification — Match
Given student "uuid-student-001" has an enrolled fingerprint template
When the student presents their finger at the terminal and BiometricAPI.verify() is called
Then the API returns result VERIFIED with confidence ≥ 80% within 3 seconds
And a bio_token is returned, valid for 10 minutes
And the verification event is logged in biometric_log
AC-BIO-03
Biometric Verification — No Match
Given student "uuid-student-002" presents student "uuid-student-001"'s finger (impersonation attempt)
When BiometricAPI.verify() is called for "uuid-student-001"
Then the API returns result FAILED
And no bio_token is issued
And the failure is logged in biometric_log with result "FAILED"
And if 3 FAILED events occur within 5 minutes for the same user, an admin alert is triggered
AC-BIO-04
Template Deletion on Account Close
Given a student account with enrolled biometric templates is deactivated by an admin
When the deactivation is confirmed
Then all biometric templates for the user are securely deleted from the vault within 5 minutes
And a deletion event is logged in both biometric_log and audit_log
And a subsequent verification attempt for this user returns TEMPLATE_NOT_FOUND

4. Admin Module

AC-ADMIN-01
Create User Account
Given I am authenticated as an Administrator
When I submit a valid user creation request with name, email, role "lecturer", and department_id
Then a new user record is created in the users table
And a staff record is created in the staff table linked to the new user
And a welcome email with a temporary password is sent within 60 seconds
And the action is recorded in audit_log with my admin user_id
AC-ADMIN-02
Approve and Publish Results
Given a result batch for CSC 301 Second Semester 2025/2026 is in pending status
When I approve the batch
Then all result records in the batch are updated to status = published
And enrolled students receive an in-portal and email notification
And students can immediately view their grades
And the approval is timestamped with my name in the batch record
AC-ADMIN-03
Reject Result Batch with Notes
Given a result batch is in pending status
When I reject the batch with notes "3 students have scores exceeding maximum CA of 30"
Then the batch status changes to returned
And the lecturer who submitted receives a notification with the rejection notes
And the lecturer can edit and resubmit within the correction window
AC-ADMIN-04
Audit Log is Immutable
Given I am authenticated as an Administrator
When I attempt to delete or update an audit_log entry via the API or directly on the database
Then the operation is rejected with an appropriate error
And the attempted modification itself is logged as a suspicious event
And an alert is sent to the VC
AC-ADMIN-05
Bulk Student Import Validation
Given I upload a CSV with 500 student records where 3 rows have duplicate matric numbers
When the system validates the file
Then import is rejected with a row-by-row error report showing the 3 duplicates
And no records are created until the file is corrected and re-uploaded
And upon successful re-upload, all 500 accounts are created with welcome emails sent

5. Lecturer Module

AC-LEC-01
Score Entry and Calculation
Given I am authenticated as a Lecturer assigned to CSC 301
When I enter CA score 25 and exam score 58 for a student
Then the system displays total 83 and grade "A" automatically
And I can save as draft without submitting
And draft scores are persisted when I navigate away and return
AC-LEC-02
Score Out of Range Rejection
Given I am on the result entry form for CSC 301
When I enter CA score 35 (exceeds maximum of 30)
Then the field is highlighted red immediately with error "CA score cannot exceed 30"
And the submit button is disabled until the value is corrected
And the invalid score is not saved
AC-LEC-03
Biometric-Verified Result Submission
Given I have entered scores for all students in CSC 301
When I click "Submit for Approval"
Then I am prompted to verify my identity via fingerprint scan
And upon successful biometric verification, the batch is submitted
And the batch status changes to pending
And the result records include bio_verified = true and my staff_id
AC-LEC-04
Attendance Session Recording
Given I start an attendance session for CSC 301 on 2026-06-05
When student 24/CSC/001 taps their NFC card and biometric verification succeeds
Then an attendance record is created with bio_verified = true, method "nfc", and session_date 2026-06-05
And the real-time counter on my screen updates from 0 to 1 present
AC-LEC-05
Result Submission Window Enforcement
Given the result submission deadline for Semester 2 has passed
When I attempt to submit a result batch
Then the submit button is disabled and a message reads "Submission window closed. Contact the registry to reopen."
And no scores can be submitted via the API either (server-side enforcement)

6. Student Module

AC-STU-01
Result Visibility After Publication
Given admin has approved and published results for 2025/2026 Second Semester
When I log in as student 24/CSC/001 and navigate to My Results
Then I see all course results with CA, exam, total, grade, and units displayed
And my CGPA is calculated and displayed correctly
And a Download Transcript button is visible if I have no outstanding fees
AC-STU-02
Transcript Download Blocked for Indebted Students
Given I am a student with a fee balance of ₦50,000
When I navigate to My Results
Then the Download Transcript button is disabled
And a message reads "Clear your outstanding balance to unlock transcript download"
And the GET /api/results/export API returns HTTP 403 if called directly
AC-STU-03
Online Fee Payment Success
Given I have an outstanding balance of ₦250,000
When I initiate a Remita payment for ₦250,000 and complete the gateway transaction
And Remita sends a successful webhook to the portal
Then my portal balance updates to ₦0 outstanding
And a payment record is created in payments with status "success"
And a PDF receipt is generated and emailed to me within 2 minutes
AC-STU-04
Attendance Warning Display
Given I have attended 8 of 12 sessions in MTH 201 (66.7% attendance)
When I view my attendance for MTH 201
Then the attendance percentage shows 66.7% highlighted in red
And a warning message reads "Below the 75% threshold required for exam eligibility"
AC-STU-05
Profile Update — Allowed Fields Only
Given I am authenticated as a student
When I attempt to update my phone number to "+2348012345678"
Then the update is saved and reflected on my profile immediately
When I attempt to change my matric number via the profile API
Then the API returns HTTP 403 — matric number is admin-managed only

7. Definition of Done

A feature is considered Done when ALL of the following conditions are met:

  • All acceptance criteria Gherkin scenarios pass in the staging environment
  • Unit test coverage for the feature's core logic is ≥ 80%
  • Integration tests cover the full API endpoint (happy path + at least 2 error paths)
  • Code has been reviewed and approved by at least 1 peer developer
  • Security review completed for any endpoint touching sensitive data (PII, payments, biometrics)
  • The feature is documented: API docs updated, relevant PRD section marked complete
  • QA Lead has signed off on the test run in staging
  • No open P1 or P2 defects exist for this feature
  • Audit log confirms the feature generates the expected log entries
  • Accessibility: interactive elements are keyboard-navigable and have ARIA labels
