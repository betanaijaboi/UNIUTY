User Stories & Use Cases

Structured user stories covering all four portal roles and the biometric subsystem. Each story follows the standard format with acceptance criteria and Gherkin scenarios for key flows.

Format: As a [role], I want to [action] so that [benefit]. Acceptance criteria use GIVEN / WHEN / THEN Gherkin notation for testable scenarios.

1. Administrator Stories

US-ADMIN-01

As an Administrator, I want to create and manage user accounts so that all staff and students have appropriate access to the portal.

  • Admin can create accounts for students, lecturers, and other admins
  • Each account requires: full name, email, role, department, and staff/matric number
  • System auto-generates a temporary password and sends it via email
  • Admin can suspend, re-activate, or permanently delete accounts
  • Account creation is recorded in the audit log with the admin's ID

When I navigate to User Management → Create User
And I fill in name "Dr. Amaka Okafor", email "a.okafor@uniuty.edu.ng", role "Lecturer", department "Computer Science"
And I click "Create Account"
Then a new user record is created in the database
And a welcome email with temporary credentials is sent to "a.okafor@uniuty.edu.ng"
And the action is recorded in the audit log
US-ADMIN-02

As an Administrator, I want to assign and change user roles so that access privileges can be updated when staff responsibilities change.

  • Admin can change any user's role from the user detail page
  • Role change requires a mandatory justification note
  • If promoting to Admin or VC role, Vice Chancellor approval is required first
  • The user is notified via email of the role change
  • Previous role history is preserved in the audit log
US-ADMIN-03

As an Administrator, I want to approve and publish semester results so that students can view their grades after quality control.

  • Admin sees a list of result batches pending review, grouped by course and semester
  • Admin can view individual scores before approving
  • Admin can flag a batch for correction and return it to the lecturer
  • On approval, results become visible to students immediately
  • Approval action is timestamped and attributed to the admin's account

When I open the pending result batch and review all scores
And I click "Approve & Publish"
Then all student records in the batch are marked published = true
And students enrolled in CSC 301 receive a result notification
And the batch shows status "Published" with my name and timestamp
US-ADMIN-04

As an Administrator, I want to manage department records and course offerings so that the academic catalogue is always accurate.

  • Admin can add, edit, or archive departments
  • Admin can create courses with code, title, credit units, level, and semester
  • Admin can assign lecturers to courses for a given session and semester
  • Archiving a department disables new enrolments but preserves historical records
US-ADMIN-05

As an Administrator, I want to configure the academic calendar so that fee deadlines and result submission windows are automatically enforced.

  • Admin can set semester start/end dates, fee due dates, and result submission deadlines
  • System blocks result submission outside the configured window
  • Automated reminders are sent 7 days and 1 day before deadlines
  • Calendar changes require VC approval if semester is already in progress
US-ADMIN-06

As an Administrator, I want to view and export the system audit log so that I can conduct security reviews and respond to disputes.

  • Audit log shows: timestamp, user ID, action type, IP address, biometric verification status
  • Admin can filter by date range, user, action type, and IP address
  • Audit log is exportable as CSV and PDF
  • Audit log entries cannot be deleted by any user including Admin
US-ADMIN-07

As an Administrator, I want to manage student admission records so that new students can be onboarded efficiently at the start of each session.

  • Admin can create admission records from JAMB/UTME data import
  • Admin can update admission status: Pending, Offered, Accepted, Rejected
  • Accepted students can be converted to active student accounts in one click
  • Rejected applicants receive an automated email notification
US-ADMIN-08

As an Administrator, I want to generate financial reconciliation reports so that the bursary can verify all payments against what is owed.

  • Report shows: total fees billed, total paid, outstanding balance per student, per department, and university-wide
  • Filterable by session, department, payment method, and payment gateway
  • Exportable as Excel and PDF
  • Report refresh is real-time, not batched
US-ADMIN-09

As an Administrator, I want to lock or unlock student accounts so that I can handle security incidents and reinstate affected students quickly.

  • Admin can manually lock/unlock any student or staff account
  • Lock reason must be entered and is stored with the action
  • Locked accounts receive an email explaining next steps
  • Unlock requires admin to re-verify the student's identity
US-ADMIN-10

As an Administrator, I want to monitor biometric enrollment coverage so that I can identify students or staff who have not yet enrolled and take action.

  • Dashboard shows % of users enrolled per biometric method
  • Admin can export a list of unenrolled users
  • Admin can send a bulk reminder email/SMS to unenrolled users
  • Coverage is broken down by department and role

2. Vice Chancellor Stories

US-VC-01

As a Vice Chancellor, I want to view an executive dashboard so that I can monitor the university's academic and financial health at a glance.

  • Dashboard shows: total active students, average CGPA by department, semester pass rate, total fees collected, attendance averages
  • Charts are interactive: click a department to drill down
  • Data refreshes every 15 minutes
  • Dashboard is accessible on mobile and tablet
Given I am logged in as Vice Chancellor
When I navigate to the Executive Dashboard
Then I see total enrollment 12,847, average CGPA 3.12, and semester pass rate 78.4%
And I can click "Computer Science" to see department-specific metrics
US-VC-02

As a Vice Chancellor, I want to approve staff role promotions so that elevated privileges are granted only with executive oversight.

  • VC receives an in-portal notification and email when a role promotion is pending
  • VC can approve or reject with a comment
  • Approval is biometric-verified before taking effect
  • Both the requesting admin and the affected user are notified of the decision
US-VC-03

As a Vice Chancellor, I want to access the full audit trail for any user or action so that I can investigate anomalies independently.

  • VC has read-only access to the complete audit log
  • VC can search by any user, action, date range, or IP
  • Log cannot be altered or deleted by VC
  • Sensitive fields (password hashes, bio templates) are never shown in the log
US-VC-04

As a Vice Chancellor, I want to receive a weekly summary report via email so that I stay informed without logging into the portal daily.

  • Email sent every Monday at 07:00 WAT
  • Report includes: new enrolments, results published this week, payments received, critical security events
  • VC can opt out or change delivery frequency from profile settings
  • Report is also accessible as a PDF download from the portal
US-VC-05

As a Vice Chancellor, I want to view departmental performance comparisons so that I can identify underperforming departments and intervene.

  • Comparison table shows all 14 departments sorted by pass rate, CGPA, attendance rate
  • VC can toggle between current semester and historical views
  • Departments below a configurable threshold are highlighted in red

3. Lecturer Stories

US-LEC-01

As a Lecturer, I want to enter student scores for my assigned courses so that results can be processed without paper score sheets.

  • Lecturer sees only courses they are assigned to for the current session/semester
  • Score entry interface shows the class list with matric numbers and student photos
  • CA score (max 30) and Exam score (max 70) entered per student
  • System auto-calculates total and grade using university grading scale
  • Scores can be saved as draft and submitted later within the window
  • Once submitted, scores are locked pending admin approval
Given I am assigned to CSC 301 for 2025/2026 Second Semester
When I open the result entry form for CSC 301
And I enter CA score 25 and exam score 58 for student 20/CSC/001
Then the system displays total 83 and grade "A"
And I can submit the batch for admin approval
US-LEC-02

As a Lecturer, I want to record student attendance via biometric scan so that proxy attendance is eliminated.

  • Lecturer initiates an attendance session for a specific course and date
  • Students tap NFC card or complete facial scan at the department terminal
  • Attendance is automatically recorded with timestamp and location
  • Lecturer sees a real-time count of present vs. registered students
  • Attendance session can be closed manually or auto-closes after 15 minutes
US-LEC-03

As a Lecturer, I want to view my class list with photos so that I can visually identify students during in-person sessions.

  • Class list shows: matric number, full name, passport photo, level, attendance percentage
  • Lecturer can search and filter by level, name, or attendance status
  • Students below 75% attendance are flagged with a warning icon
US-LEC-04

As a Lecturer, I want to edit submitted scores within an approved amendment window so that I can correct genuine errors before final ratification.

  • Amendment window is configurable by admin (default: 48 hours after submission)
  • Each edit is logged with before/after values and reason
  • After the window closes, edits require admin intervention
  • Students are not notified of score edits until admin approves and publishes
US-LEC-05

As a Lecturer, I want to export my class attendance report as PDF so that I have a document ready for Senate board submissions.

  • Report includes: student list, per-session attendance, total sessions, percentage for each student
  • Report is stamped with course code, semester, and lecturer name
  • PDF is downloadable and email-deliverable
US-LEC-06

As a Lecturer, I want to verify student identity via biometric at exam entry so that impersonation is immediately detected and prevented.

  • Lecturer activates "Exam Check-in" mode for a course
  • Student presents biometric (fingerprint, retina, or facial)
  • System returns: VERIFIED / FAILED with student photo and name
  • Failed verifications are logged and flagged for admin review
  • Each check-in event is recorded in biometric_log
US-LEC-07

As a Lecturer, I want to receive notifications when my result submissions are approved or returned for correction so that I can respond quickly.

  • Email and in-portal notification on approval or rejection
  • Rejection notification includes admin's correction notes
  • Correction deadline is included in the notification
US-LEC-08

As a Lecturer, I want to see a summary of each student's performance across all my courses so that I can identify at-risk students early.

  • Summary shows CGPA, current semester average, attendance rate, and payment status (cleared/not cleared)
  • At-risk students (CGPA below 1.5 or attendance below 50%) are highlighted
  • Lecturer can flag a student for pastoral support referral
US-LEC-09

As a Lecturer, I want to view the results submission deadline for each course so that I never miss the window.

  • Deadline is visible on the results entry page with a countdown timer
  • Reminder email sent 3 days before the deadline for any course with unsaved scores
  • After the deadline, the form is disabled and shows a message to contact admin
US-LEC-10

As a Lecturer, I want to upload supplementary score sheets as a CSV file so that I can use my existing spreadsheet workflow and minimise re-entry.

  • CSV template is downloadable from the result entry page
  • System validates: matric numbers match enrolled students, scores are within range
  • Validation errors are listed row by row before import is accepted
  • Successful upload pre-fills the form for final review before submission

4. Student Stories

US-STU-01

As a Student, I want to view my semester results as soon as they are published so that I know my academic standing without visiting the registry.

  • Results page shows all courses for the selected semester: course code, title, CA, exam, total, grade, and units
  • CGPA is calculated and displayed for the current and cumulative levels
  • Results are accessible immediately after admin publishes them
  • Student receives an email and in-portal notification when results are published

And a "Download Transcript" button is available
US-STU-02

As a Student, I want to download an official result transcript as a PDF so that I have a document for job applications and postgraduate admissions.

  • Transcript PDF includes: university letterhead, student bio, all semesters, CGPAs, and a verification QR code
  • QR code links to a verification page on the UNIUTY domain
  • Download is only available for students with no outstanding fees (cleared)
  • Each download is logged in the audit trail
US-STU-03

As a Student, I want to pay my school fees online so that I don't have to visit the bank or join bursary queues.

  • Fee payment page shows: total fee, amount paid, outstanding balance, due date
  • Student can choose Remita or Flutterwave as payment gateway
  • On successful payment, portal balance updates in real time
  • Payment receipt is automatically generated as PDF
  • Student receives email confirmation with transaction reference

Then my portal balance updates to ₦0 outstanding

US-STU-04

As a Student, I want to check my attendance status for each course so that I can monitor my standing and avoid disqualification from exams.

  • Attendance page shows per-course: sessions held, sessions attended, percentage
  • Courses below 75% are highlighted with a red warning
  • Breakdown of each attendance session (date, method, verified/not) is available
  • Student cannot modify attendance records
US-STU-05

As a Student, I want to update my profile information so that my contact details are always current.

  • Student can update: phone number, alternate email, home address, next-of-kin
  • Name, matric number, department, and level are read-only (admin-managed)
  • Profile photo can be uploaded (max 2MB, JPEG/PNG)
  • Updates are saved immediately and reflected across the portal
US-STU-06

As a Student, I want to view my course registration for the current semester so that I can confirm my enrolled courses are correct.

  • Course registration page shows: course code, title, units, day/time, venue, assigned lecturer
  • Total registered credit units displayed and compared against maximum allowed
  • Any discrepancy can be flagged to admin via a built-in query form
US-STU-07

As a Student, I want to receive notifications for important events so that I never miss deadlines or announcements.

  • Notifications delivered via in-portal bell icon and email
  • Event types: result published, payment due, attendance warning, account locked
  • Student can configure which notification types they receive
  • Unread notifications are badged in the nav
US-STU-08

As a Student, I want to reset my password via email so that I can regain access without visiting the ICT office.

  • Reset link sent to registered email within 60 seconds of request
  • Reset link expires after 15 minutes and is single-use
  • New password must meet complexity requirements: 8+ chars, 1 uppercase, 1 number, 1 special char
  • Password change invalidates all existing sessions
US-STU-09

As a Student, I want to view my full academic history across all semesters so that I can track my progress toward graduation.

  • Academic history shows all semesters from year 1, sorted chronologically
  • Each semester shows: courses, grades, semester GPA, credit units, and cumulative CGPA
  • Expected graduation year is calculated and displayed based on current level
US-STU-10

As a Student, I want to view my biometric enrollment status so that I know which methods I have registered and can book an enrollment session if needed.

  • Profile page shows status for each biometric method: Fingerprint, Retina, Facial, NFC
  • Enrolled methods show enrollment date; unenrolled show a "Book Enrollment" button
  • Booking links to a departmental enrollment calendar

5. Biometric System Stories

US-BIO-01

As a System Administrator, I want the biometric hardware to communicate with the portal via a standardised plugin API so that different hardware vendors can be supported without code changes.

  • BiometricAPI exposes a standard interface: enroll(), verify(), delete(), getLog()
  • Hardware driver registered as a plugin module at server startup
  • If plugin fails to initialise, system falls back to PIN-based verification with an alert to admin
  • API version is negotiated at handshake; backward-compatible for 2 major versions
Given a Suprema BioStation biometric device is connected and driver loaded
When the portal starts and calls BiometricAPI.init()
Then the device handshake succeeds within 5 seconds
And the audit log records "Biometric device online — Suprema BioStation v2.3"
US-BIO-02

As an Administrator, I want to enroll a student's biometric templates so that they can be verified during exams and attendance.

  • Enrollment captures 3 samples per method and creates a combined template
  • Template quality score must be ≥ 70% for enrollment to succeed
  • Template is stored encrypted (AES-256) and never transmitted in plaintext
  • Enrollment logged in biometric_log with method, quality score, and admin ID
  • Student must present valid ID card during enrollment session
US-BIO-03

As a System, I want to verify a user's biometric in under 3 seconds so that queues do not form at exam and attendance checkpoints.

  • 1:1 verification (template match against known user) completes in < 1.5s
  • 1:N identification (unknown vs. full database) completes in < 3s for up to 15,000 records
  • If verification exceeds 5s, the system returns a timeout error and logs the event
  • Response includes: match result, confidence score, user ID (if matched)
US-BIO-04

As an Administrator, I want to delete a user's biometric templates when their account is closed so that their biometric data is not retained.

  • Template deletion is triggered automatically on account deactivation
  • Admin can also manually trigger deletion from the user profile
  • Deletion is irreversible; user must re-enroll if account is reactivated
  • Deletion event logged in biometric_log and audit_log
  • NDPR Article 17 (right to erasure) is satisfied by this process
US-BIO-05

As a System, I want to log every biometric event with full metadata so that security audits can trace any verification attempt.

  • Log captures: user_id, method, purpose, location, result, quality_score, template_hash, timestamp
  • Failed verification events are flagged and trigger an alert if 3 failures occur for same user within 5 minutes
  • Log is append-only; no entry can be modified or deleted
  • Log is accessible to Admin and VC; not visible to Lecturers or Students
