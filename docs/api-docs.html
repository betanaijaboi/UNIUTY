API Documentation

Complete REST API reference for the UNIUTY Portal backend. All endpoints return JSON. Authentication is required for all endpoints unless marked public.

1. Overview

PropertyValue
Base URL (Production)https://api.uniuty.edu.ng/api/v1
Base URL (Staging)https://staging-api.uniuty.edu.ng/api/v1
ProtocolHTTPS only (HTTP redirected to HTTPS)
Content-Typeapplication/json
AuthenticationBearer JWT in Authorization header
Rate Limiting100 requests/minute per IP; 20 requests/minute for auth endpoints
API VersioningURL path versioning (/v1/); breaking changes bump to /v2/

2. Authentication

The API uses JWT Bearer tokens. Obtain a token via POST /api/auth/login. Include the token in every subsequent request:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Tokens expire after 8 hours. Use the refresh token (stored in an HttpOnly cookie) to obtain a new access token via POST /api/auth/refresh without re-login.

Biometric-Required Actions: Certain endpoints (result submission, role changes, VC approvals) require an additional X-Bio-Token header containing a short-lived biometric verification token obtained from POST /api/biometric/scan.

3. Auth Endpoints

POST /api/auth/login Authenticate a user and receive a JWT access token

Public No authentication required.

FieldTypeRequiredDescription
portal_idstringYesUser's Portal ID (e.g. STU-2024-001)
passwordstringYesUser's password
 
{
  "portal_id": "STU-2024-001",
  "password": "SecurePass@123"
}

200 Response:

{
  "success": true,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiJ9...",
    "token_type": "Bearer",
    "expires_in": 28800,
    "user": {
      "user_id": "uuid-...",
      "name": "Chioma Eze",
      "role": "student",
      "portal_id": "STU-2024-001"
    }
  }
}
POST /api/auth/logout Invalidate the current session token

Auth Required Adds the current JWT to the Redis denylist.

200 Response:

{ "success": true, "message": "Logged out successfully" }
POST /api/auth/refresh Obtain a new access token using the refresh token cookie

Cookie Auth The refresh token is read from the uniuty_rt HttpOnly cookie.

200 Response:

{ "success": true, "data": { "access_token": "eyJ...", "expires_in": 28800 } }
POST /api/auth/forgot-password Request a password reset OTP via email

Public Rate limited to 3 requests per hour per IP.

FieldTypeRequiredDescription
portal_idstringYes*User's Portal ID
emailstringYes*Registered email (*one of portal_id or email required)

200 Response (same whether user exists or not):

{ "success": true, "message": "If that account exists, a reset OTP has been sent." }
POST /api/auth/reset-password Reset password using OTP token
FieldTypeRequiredDescription
otpstringYes6-digit OTP from email
reset_tokenstringYesToken returned with OTP email (expires 15 min)
new_passwordstringYesNew password (min 8 chars, 1 uppercase, 1 number, 1 special)

4. User Endpoints

GET /api/users List all users with optional filters

Admin / VC only

Query ParamTypeDescription
rolestringFilter by role: student | lecturer | admin | vc
department_iduuidFilter by department
statusstringactive | suspended | locked
pageintPage number (default 1)
limitintResults per page (default 50, max 200)
GET /api/users/:id Get a single user by ID

Admin / VC or the user themselves.

200 Response:

{
  "success": true,
  "data": {
    "user_id": "3f2e1d...",
    "portal_id": "STU-2024-001",
    "name": "Chioma Eze",
    "email": "c.eze@uniuty.edu.ng",
    "role": "student",
    "created_at": "2024-09-01T08:00:00Z",
    "profile": {
      "matric_number": "24/CSC/001",
      "department": "Computer Science",
      "level": 100,
      "cgpa": 3.87
    }
  }
}
POST /api/users Create a new user account

Admin only

FieldTypeRequiredDescription
namestringYesFull name
emailstringYesInstitutional email address
rolestringYesstudent | lecturer | admin | vc
department_iduuidYesDepartment UUID
matric_numberstringCond.Required if role = student
staff_numberstringCond.Required if role = lecturer | admin
PUT /api/users/:id Update user profile details

Admin or the user themselves (limited fields).

DELETE /api/users/:id Deactivate a user account

Admin only Soft deletes — sets status to deactivated. Biometric templates are automatically purged.

PUT /api/users/:id/role Change a user's role

Admin (requires VC approval for Admin/VC promotions). Requires X-Bio-Token header.

FieldTypeRequiredDescription
new_rolestringYesTarget role
justificationstringYesReason for role change (min 20 chars)

Query ParamTypeDescription

Lecturer only Requires X-Bio-Token header for final submission.

    "status": "pending",
    "records_submitted": 87,
    "submitted_at": "2026-01-15T14:32:00Z"

GET /api/results/:studentId Get all published results for a student

Student (own results only) | Admin / VC / Lecturer (assigned course students)

PUT /api/results/:id Approve, reject, or update a result record

Admin only for approval/rejection. Lecturer can edit within amendment window.

FieldTypeDescription
actionstringapprove | reject | edit
notesstringRequired for rejection; optional for approval
GET /api/results/export Export result transcript as PDF

Returns a PDF file stream. Student must have no outstanding fees (cleared status).

Query ParamTypeDescription
student_iduuidTarget student (Admin) or omit for own (Student)
formatstringpdf | csv (default: pdf)

6. Biometric Endpoints

POST /api/biometric/scan Perform a biometric verification scan

Terminal Auth Called from authenticated biometric terminal devices.

FieldTypeRequiredDescription
user_iduuidYesUser to verify (1:1 mode)
methodstringYesfingerprint | retina | facial | nfc
purposestringYeslogin | exam | attendance | approval
locationstringYesTerminal location identifier

200 Response:

{
  "success": true,
  "data": {
    "result": "VERIFIED",
    "confidence": 98.4,
    "bio_token": "short-lived-token-abc123",

  }
}
POST /api/biometric/enroll Enroll a user's biometric template

Admin only Must be performed at a registered terminal.

FieldTypeRequiredDescription
user_iduuidYesUser to enroll
methodstringYesfingerprint | retina | facial | nfc
samplesarrayYes3 biometric sample payloads from the device driver
DELETE /api/biometric/:userId/:method Delete a user's biometric template for a specific method

Admin only Irreversible. Triggers audit log entry. Use all as method to delete all templates.

GET /api/biometric/log Retrieve biometric event log

Admin / VC only

Query ParamTypeDescription
user_iduuidFilter by user
methodstringFilter by biometric method
resultstringVERIFIED | FAILED
fromISO8601Start date
toISO8601End date

8. Error Codes

HTTP StatusError CodeMeaningCommon Causes
400BAD_REQUESTMalformed requestMissing required fields, invalid JSON, wrong data types
401UNAUTHORIZEDAuthentication required or token expiredMissing Authorization header, expired JWT, invalid token signature
403FORBIDDENInsufficient permissionsRole does not have access to this resource or action
404NOT_FOUNDResource not foundInvalid UUID, deleted resource, wrong endpoint path
409CONFLICTResource already existsDuplicate email, matric number, or payment reference
422UNPROCESSABLEValidation failedScore out of range, invalid semester value, password too weak
429RATE_LIMITEDToo many requestsExceeded 100 req/min per IP or 20 req/min for auth endpoints
500SERVER_ERRORInternal server errorUnhandled exception; check Sentry for trace ID

All error responses follow this structure:

{
  "success": false,
  "error": {
    "code": "FORBIDDEN",
    "message": "You do not have permission to perform this action.",
    "trace_id": "sentry-trace-abc123"
  }
}
